# Model and Audio Technology Comparison

**Checked 27 November 2026.** “Current” claims below refer to the linked upstream pages as available at research time. Pin model revisions and audit checkpoint/voice licenses independently; this comparison is an engineering shortlist, not a legal opinion. Latency and hardware descriptions are qualitative unless the upstream source states a measured value. Benchmark locally before choosing defaults.

## A. Speech recognition (audio-to-text)

| Option                                                       | Accuracy / languages                                                                                                                   | Streaming and latency                                                                                                                     | CPU / GPU                                                                                            | License and practical use                                                                                                                                                |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Whisper](https://github.com/openai/whisper)                 | Strong general multilingual baseline; language detection and translation/transcription tasks; timestamps at segment level              | Original inference is chunked/offline, not native incremental streaming                                                                   | Tiny/base on CPU; medium/large benefit greatly from GPU; largest checkpoints need substantial memory | Code and released weights MIT per upstream. Best high-quality offline baseline; verify hallucination behavior and domain data.                                           |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper)  | Same Whisper model family, CTranslate2 runtime; multilingual and timestamps                                                            | Batch/segment transcription with VAD options; not true streaming by itself                                                                | CPU int8 works, GPU FP16/INT8 is much faster; CUDA/cuDNN compatibility adds deployment work          | Runtime MIT; checkpoint terms follow Whisper. Recommended offline implementation.                                                                                        |
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp)       | Whisper family; quantized GGML models; broad platforms                                                                                 | Includes microphone/stream examples, but incremental output is chunk/rolling-window behavior, not a purpose-built streaming ASR guarantee | Good quantized CPU/Metal/CUDA options, embedded friendly                                             | MIT. Strong cross-platform fallback, especially where Python is undesirable.                                                                                             |
| [NVIDIA NeMo Speech](https://github.com/NVIDIA-NeMo/Speech)  | Multiple CTC/RNNT/Conformer/Parakeet and newer speech models; checkpoint-specific language coverage and accuracy                       | Includes streaming/chunked ASR model families; model- and recipe-specific                                                                 | Often CUDA/PyTorch; model export/runtime options are improving; greater integration complexity       | Framework Apache-2.0; model/checkpoint license can differ. Best candidate to benchmark for low-latency server ASR when GPU/NVIDIA stack is acceptable.                   |
| [NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) | Native inference for listed NeMo checkpoints                                                                                           | Streaming models listed upstream; early-moving ecosystem, confirm checkpoint support                                                      | C++/ggml path targets local deployment; platform/model support varies                                | Inspect runtime and each checkpoint license. Potentially reduces Python dependency; validate maturity.                                                                   |
| [Vosk](https://github.com/alphacep/vosk-api)                 | Language-specific Kaldi models; quality is variable and often behind Whisper/strong newer models on difficult noisy multilingual audio | Genuine incremental recognition, small partials, offline                                                                                  | CPU-friendly and small models; no GPU needed for common cases                                        | API Apache-2.0; check each downloaded language model card/license. Useful low-resource real-time baseline and vocabulary adaptation, not best universal offline quality. |

**Recommendation:** offline transcription = faster-whisper with large-v3 on GPU when available, medium/small or quantized whisper.cpp on CPU; choose after measuring WER on representative audio. Real-time partials = Vosk as lightweight baseline or a current NeMo streaming checkpoint for quality/scale. A practical hybrid can show partial Vosk/streaming-ASR text then replace it with final faster-whisper text. Partial stability and final transcript are separate event types. Diarization is a separate provider/stage (e.g. pyannote-family models with their own terms and model access conditions); it is not implied by ASR support.

Whisper drawbacks: it is not native streaming, may be slow on CPU at large sizes, and can hallucinate on silence/noise. Language support does not guarantee equal accuracy across languages. Timestamp precision and word alignment depend on implementation. Evaluate real data, including accents, noise, names, and code switching.

## B. Speech-to-speech and audio conversation

| System                                                                                              | What it actually does                                                                                                                                         | Streaming / interaction                                                                                                                                                                                                    | License, compute, caveat                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Qwen2.5-Omni](https://github.com/QwenLM/Qwen2.5-Omni)                                              | Multimodal model accepts audio (also other modalities), generates text and natural speech; genuine audio-in/audio-out capability, not merely ASR+TTS branding | Upstream describes real-time streaming speech generation; verify exact serving stack, duplex behavior, interruption/cancellation and sustained latency. Streaming output does not by itself prove full-duplex turn-taking. | Upstream GitHub reports Apache-2.0. 7B-class checkpoint is GPU-heavy; source primarily uses Python/Transformers ecosystem. Strong first direct audio experiment.                                                          |
| [Kyutai Moshi](https://github.com/kyutai-labs/moshi)                                                | Speech-text foundation model plus Mimi codec; directly models user and assistant streams                                                                      | Explicit full-duplex spoken dialogue, designed to listen while speaking; theoretical ~160 ms / practical ~200 ms reported in paper, not a guarantee on arbitrary hardware/network.                                         | Model weights CC-BY-4.0 per upstream; code/runtime license differs by component/version. GPU needs and backend-specific quantization matter; official Windows support limited. Verify commercial attribution obligations. |
| [Qwen2-Audio](https://github.com/QwenLM/Qwen2-Audio)                                                | Audio perception/chat and audio instruction tasks                                                                                                             | Audio understanding and generated text are not equivalent to conversational speech output; check a concrete checkpoint/task before calling it speech-to-speech                                                             | License and runtime per repo/checkpoint. Not preferred over Omni for generated spoken dialogue.                                                                                                                           |
| [Kyutai Unmute / delayed-streams-modeling](https://github.com/kyutai-labs/delayed-streams-modeling) | Streaming speech-text components that can support STT/TTS/LLM pipelines                                                                                       | Realtime component stack; not one model magically supplying all agent logic                                                                                                                                                | Weights and subcomponents have separate terms. Consider when composable streaming is preferable to Moshi.                                                                                                                 |
| Audio-capable Hugging Face models generally                                                         | Task-specific models may do audio classification, captioning, ASR, audio QA, or TTS                                                                           | “Audio input” does not mean speech generation, streaming, or full duplex. Inspect task, generation tokens, serving examples, and interruption semantics.                                                                   | Each model card license governs. Do not extrapolate one model's license to a collection.                                                                                                                                  |

**Terminology:** (1) ASR emits recognized text. (2) Audio understanding answers questions about audio or classifies it. (3) TTS takes text and synthesizes speech. (4) Speech-to-speech means a model/system accepts speech and produces speech, often with text reasoning hidden or exposed. (5) Full-duplex means input listening can continue during output; it requires turn/interruption behavior and is not established by chunked TTS alone.

**Recommendation:** ship ASR → LLM → TTS first because components are observable, replaceable, and easier to run on moderate hardware. Run Qwen2.5-Omni and Moshi as separate adapters behind `SpeechToSpeechProvider`; compare first-audio latency, interruption recovery, intelligibility, multilingual performance, VRAM, and license fit. Moshi is clearest full-duplex research option; Qwen2.5-Omni is the compelling multimodal/audio-output option. Neither is the MVP default until measured.

| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)               | Small, high quality for size; good low-latency preset voices; v1.0 model card lists multiple languages/voices, but frontend and pronunciation quality vary | Preset voice packs, not arbitrary reference-voice cloning                   | CPU-friendly relative to large TTS; weights Apache-2.0. Piper engine license and each voice license must be reviewed independently. Good small-device fallback.                                                             |
| [Coqui XTTS v2](https://github.com/coqui-ai/TTS)                      | Multilingual and can sound natural; heavier than Kokoro/Piper                                                                                              | Few-second reference voice cloning                                          | Model is CPML, noncommercial-only; upstream model metadata requires TOS acceptance. Do not choose for a commercial product absent a compatible license. Community maintenance does not relicense weights. |
| [Kyutai TTS](https://github.com/kyutai-labs/delayed-streams-modeling) | Streaming TTS architecture with low-latency generation; language/model-card-specific                                                                       | Some variants support voice conditioning/cloning; check intended checkpoint | Python ecosystem and model-size/runtime requirements; model weights may use CC-BY-4.0. Useful experimental alternative where license fits.                                                                |

Use chunked TTS with sentence/clause boundaries, retain text/audio sequence numbers, and avoid concatenating raw independently synthesized chunks without a small crossfade or codec-aware handling. Voice cloning requires explicit rights/consent and abuse controls even when a model permits it technically.

## D. Audio transport and processing

| Tool                                              | Role and recommendation                                                                                                                                                                                                                                                            |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser `getUserMedia` + Web Audio `AudioWorklet` | Capture PCM with predictable framing/resampling; browser owns permission and device UI. Avoid deprecated ScriptProcessorNode. This is browser code, not Express server functionality.                                                                                              |
| WebSocket (`ws`)                                  | Good fit for duplex app events and audio chunks. Use WSS in production, explicit origin/auth checks, message limits, sequence IDs, bounded queue, heartbeat, cancellation, and backpressure.                                                                                       |
| Socket.IO                                         | Use only if rooms/fallback/reconnection abstractions are valuable. It is not wire-compatible with raw WebSocket or Micdrop plain `ws`; otherwise avoid another protocol layer.                                                                                                     |
| WebRTC                                            | Consider later for browser-to-server media transport at scale or network adversity; adds signaling, ICE/TURN and operational complexity. Not needed for a local first MVP.                                                                                                         |
| VAD: WebRTC VAD / Silero                          | WebRTC VAD is compact/classical and format-sensitive. Silero offers neural VAD, including ONNX options and Node-compatible runtime paths, with MIT upstream repo but verify exact model artifact terms. VAD detects speech activity, not semantic end-of-turn or speaker identity. |
| FFmpeg                                            | Decode/normalize WAV, WebM/Opus, MP3 and practical uploads; fixed argument array, no shell interpolation, resource/time limits. Default build is LGPL; optional codecs/components can change license.                                                                              |
| Audio resampling                                  | Convert to the provider's required mono/sample rate (often 16 kHz ASR, 24 kHz generation) with a tested library/FFmpeg. Preserve original metadata and avoid silently changing channel layout.                                                                                     |
| Denoising                                         | Defer initially; noise suppression can damage speech. Add browser echo cancellation/noise suppression constraints and compare enhancement only against noisy validation data.                                                                                                      |
| Diarization / merge                               | Separate optional stage. Keep timestamps, speaker labels, and source offsets. Merge chunked audio with sample-accurate offsets; do not infer diarization from VAD.                                                                                                                 |

## Micdrop identity and fit

Identified project: [Godefroy/micdrop](https://github.com/Godefroy/micdrop), [docs](https://micdrop.dev/docs/client). MIT TypeScript SDK; web/React Native client, Node server packages, VAD, audio transport/playback, turn taking, barge-in/echo handling, reconnection, and provider adapters. README says server can work with plain `ws`, Fastify, or NestJS; Express can share an HTTP server with `ws`, but this exact combination should be proven in a small spike. It improves capture/session plumbing and some pipeline orchestration. It does not replace Express API/business logic, FFmpeg, model-serving, file storage, or licensing review. It advertises a local provider catalog, but each provider and its weights need verification. “MicDrop” remains ambiguous if the user meant another repository/package.
